# 📋 マニフェスト帳簿（産業廃棄物処分業者向け）

中間処理・最終処分を行う処分業者が、受託したマニフェスト（紙・電子）の処理状況、
二次マニフェスト、法定帳簿をまとめて管理するための Web アプリです。1社での利用を想定しています。

## 主な機能

| 画面 | 内容 |
|---|---|
| ダッシュボード | 期限超過・期限間近の手続き一覧（その場で完了登録）、業許可・委託契約の期限、帳簿の記載漏れ |
| 受託マニフェスト | 紙／電子の受託分を登録。受入（計量値）→ 処分終了 → C2・D票送付／処分終了報告 → 最終処分 → E票送付／最終処分終了報告 までの期限を自動計算 |
| 二次マニフェスト | 処分後物を委託するときのマニフェスト。元の受託マニフェストと紐付け（按分量つき）。E票（最終処分終了）を受領すると、紐付いた受託マニフェストに最終処分の日付・場所を自動反映 |
| 帳簿 | 施行規則第10条の8の記載事項（受入・処分・持出の明細、受入先ごと・処分方法ごと・持出先ごとの集計）を事業場・月／年度で表示。CSV出力・印刷・年度ごとの閉鎖 |
| JWNET連携 | 処分終了報告・最終処分終了報告・二次マニフェスト登録の送信キュー。送信前チェック（2027年4月からの必須項目を含む）。JWNETのマニフェスト情報CSVの取込 |
| マスタ | 自社情報、処分事業場（許可番号・期限）、取引先（排出事業者・収集運搬・二次委託先）、排出事業場、委託契約 |
| ユーザー／操作履歴 | 管理者・一般の権限、すべての変更を操作履歴に記録 |

### 管理している期限

| 手続き | 期限 |
|---|---|
| 紙：C2票（運搬業者へ）・D票（排出事業者へ）送付 | 処分終了日から10日以内 |
| 紙：E票送付 | 最終処分終了の報告を受けた日から10日以内（自社で最終処分した場合は処分終了日から） |
| 電子：処分終了報告 | 処分終了日から3日以内（土日祝・12/29〜1/3を除く） |
| 電子：最終処分終了報告 | 最終処分終了の報告を受けた日から3日以内（同上） |
| 二次（電子）：JWNET登録 | 引渡しから3日以内（同上） |
| 二次：B2・D票／運搬・処分終了報告の確認 | 交付日から90日（特別管理産業廃棄物は60日） |
| 二次：E票／最終処分終了報告の確認 | 交付日から180日 |
| 二次：措置内容等報告書 | 上記の確認期限から30日以内 |
| 帳簿 | 翌月末までに記載、1年ごとに閉鎖、閉鎖後5年間保存 |

> 法令の要点をもとに実装しています。運用前に最新の法令・JWNETの案内・自治体の指導内容を確認してください。

## JWNET連携について

`JWNET_MODE` で接続方法を切り替えます。

- `mock`（既定）: 開発・デモ用。送信すると即「受付済」になり、マニフェストの報告日が埋まります。
- `manual`: 送信内容を画面に表示し、担当者が JWNET の Web 画面で入力したあと「入力済にする」を押す運用です。**すぐ本番で使うならこのモード**です。
- `edi`: 未実装。JWNET の EDI 方式は、EDI 利用申込のうえ「EDI方式接続仕様書」に基づくファイル交換（全銀協標準プロトコル拡張Z手順など）で接続します。仕様書を入手したら `src/lib/jwnet/gateway.ts` の `EdiGateway` を実装してください。

2027年4月1日施行の省令改正で、処分終了報告・最終処分終了報告に「処分事業場の情報・処分方法と処分量・中間処理後物の種類と量」が必須になります。
送信内容（`src/lib/jwnet/payload.ts`）はこれらを含めて組み立て、不足があれば送信前に止めます。

## 技術構成

- Next.js 16（App Router・Server Actions）/ React 19 / TypeScript
- PostgreSQL + Drizzle ORM（マイグレーションは `drizzle/`）
- 認証：ID・パスワード（scrypt）＋ DB セッション
- テスト：Vitest（期限計算・帳簿集計・CSV・JWNET送信前チェック）

```
src/
  lib/domain/   期限計算・帳簿集計など法令ロジック（DBに依存しない純粋関数）
  lib/jwnet/    JWNET送信内容・接続口・CSV
  actions/      Server Actions（保存・完了登録・送信など）
  app/          画面
  db/schema.ts  テーブル定義
scripts/        マイグレーション・デモデータ・ユーザー作成
```

## セットアップ

```bash
cd manifest-service
npm install
cp .env.example .env          # DATABASE_URL を自分の PostgreSQL に合わせる
createdb manifest              # データベースを作成
set -a; . ./.env; set +a
npm run db:migrate             # テーブル作成
npm run db:seed                # （任意）デモデータ。admin / admin1234 でログイン
npm run dev                    # http://localhost:3000
```

デモデータを入れない場合は、初回アクセス時に管理者アカウントの作成画面が表示されます。
パスワードを忘れたときは `npm run user:create -- <ログインID> <新パスワード> admin` で再設定できます。

### 開発コマンド

```bash
npm test          # ユニットテスト
npm run lint      # 型チェック
npm run build     # 本番ビルド
npm run db:generate   # schema.ts を変更したらマイグレーションを生成
```

## 本番運用に向けて

- PostgreSQL は自動バックアップのあるマネージドサービス（5年間の保存義務があるため）を推奨します。
- HTTPS で公開し、`NODE_ENV=production` で動かしてください（セッションCookieが Secure になります）。
